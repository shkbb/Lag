# Lag → Rust: план переписування 1 в 1

Гілка `rust-rewrite` (від `release/1.8.0`, локально, не пушиться без «так»).
C#-версія в `InstantReplay/` заморожена й лишається еталоном для A/B-порівнянь.

## Рішення (2026-11-16)

| Що | Вибір | Чому |
|---|---|---|
| UI | **Slint** (femtovg/OpenGL рендер) | декларативна розмітка ≈ AXAML → екрани переносяться майже рядок у рядок; нативно, без Chromium |
| Плеєр/редактор | **libmpv** (render API → OpenGL-текстура в Slint) | ініт ~50 мс замість ~10 с у libVLC, d3d11va декод, точний seek |
| Тулчейн | `x86_64-pc-windows-gnu` (LLVM-MinGW/WinLibs) | MSVC на ПК немає; windows-rs, Slint/femtovg, mpv/FFmpeg DLL працюють на gnu |
| WinAPI | `windows` crate (WGC, D3D11, DXGI, WASAPI, хоткеї, трей) | офіційні біндинги, той самий API, що зараз через SharpDX/NAudio |
| FFmpeg | ті самі DLL 7.1 (`avcodec-61` …) з `InstantReplay/ffmpeg/`, біндинги згенеровані bindgen один раз і закомічені | збірка не залежить від libclang |
| C# 1.8.0 | заморожено; 1.7.1 лишається основним релізом | усі сили в Rust |

## Що зберігаємо сумісним (щоб користувач нічого не помітив)

- `%AppData%\Lag\settings.json` — той самий формат і ключі (читаємо старий файл як є).
- `%LocalAppData%\Lag\metadata\<hash>.json` — сайдкари кліпів, той самий хеш і схема.
- `%LocalAppData%\Lag\thumbnails` — кеш мініатюр.
- Логи в Documents (як `FileLog`), ті самі префікси рядків (`[stall]`, тощо) — щоб старі інструменти аналізу працювали.
- Структура MP4: ті самі треки (video, System, Microphone, All 192k), назви треків, колірні теги, cadence grid.
- Інсталятор Inno з асетом `Lag-win-Setup.exe` → автооновлення 1.7.x підхопить Rust-версію.
- 17 мов (Assets/Langs/*.axaml → конвертуємо автоматично).

## Структура `lag-rs/`

```
lag-rs/
  Cargo.toml            workspace
  crates/
    lag-ffi/            FFmpeg + libmpv біндинги (згенеровані), завантаження DLL
    lag-core/           settings, metadata, локалізація, лог, моделі, пресети
    lag-capture/        рушій: WGC → D3D11 → NV12 → NVENC, аудіо, ring buffer, mux, cadence, carry-over, stall
    lag-player/         mpv-плеєр + рендер у текстуру для Slint
    lag-app/            exe: Slint UI, трей, тости, хоткеї, оновлення
  docs/
    PLAN.md
    spec/*.md           специфікація 1-в-1 по областях (чекліст паритету)
```

## Фази

0. **Специфікація + спайки.** codex/agy витягують з C# повну специфікацію по 5 областях (`docs/spec/`).
   Паралельно спайки на ризики: (a) Slint-вікно + mpv-текстура @120 fps; (b) WGC→NVENC у Rust,
   fps/мс на кадр проти C# на тій самій грі. **Ворота:** якщо спайк не тягне, дізнаємось зараз, а не через місяць.
1. **lag-core:** settings/metadata/локалізація з тестами на сумісність зі справжніми файлами.
2. **lag-capture:** порт рушія + порт headless-самоперевірок (CARRY/CADENCE/STALL/GC…) як `cargo test` і бінарників.
   A/B проти C# на одній грі: framemd5, розподіл інтервалів кадрів, бітрейт, синхрон A/V.
3. **Оболонка:** головне вікно, трей, тости, хоткеї, налаштування.
4. **Бібліотека + плеєр.**
5. **Редактор.**
6. **Інсталятор/оновлювач**, перенесення даних.
7. **Паритет-прохід** по всіх чеклістах → pre-release 2.0.0 → основний реліз після реальної гри.

## Правила (з минулих сесій, діють і тут)

- Рушій: спершу виміряти, потім міняти; кожну зміну перевіряти цифрами.
- Пуш/теги/релізи тільки з «так». Нічого не видаляти без дозволу.
- Мишею/клавіатурою на ПК не керувати, візуально перевіряє користувач.
